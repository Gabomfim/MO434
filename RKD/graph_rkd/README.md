# Graph-RKD — choosing the number of nodes (N) and combinatorics

Generalization of Relational Knowledge Distillation: each **node** is an object
(a batch sample), each **edge** is the distance between the embeddings of two
objects, the graph is complete and undirected, and its embedding is **permutation-
invariant** (same set of nodes ⇒ same embedding). Hence a graph is a
*set* of N nodes, not an ordered tuple.

The *embedding* methods for these graphs come later; this package covers the
**choice of N** (binary search) and the **combinatorial analysis**.

## Combinatorics (and an important correction)

For a batch of B samples and graphs of N nodes:

| | formula | B=128, N=8 |
|---|---|---|
| unique graphs (sets — new method) | `C(B, N)` | 1.43×10¹² |
| ordered N-tuples (traditional RKD) | `P(B, N) = N!·C(B, N)` | 5.76×10¹⁶ |

- The number of unique graphs is **`C(B, N)`** — combinatorial, with a **peak at N = B/2**
  (`C(128,64) ≈ 2.4×10³⁷`). That is, the *space* of possible graphs is **not**
  small nor "non-exponential".
- The real advantage of permutation invariance is the **N! factor**: each graph
  replaces N! ordered tuples. In traditional RKD, ordered N-ary relations
  cost O(Bᴺ) (exponential in N); with sets you process each graph once.
- And the **per-step cost** only avoids exploding if you **sample a fixed number of graphs**
  (or partition the batch) instead of enumerating `C(B,N)`. See the cost model.

Plot `C(128,N)` vs `P(128,N)`: ![unique graphs](unique_graphs_128.png)
(generated by `plot_unique_graphs(128)`).

## Binary search for the best N

Binary search finds a **monotonic frontier**, not the maximum of a monotonic
function. Since we assume quality grows with N, "best N" = **largest N
feasible under a constraint** (compute/memory budget). `find_best_n` does
this in O(log B) evaluations:

```python
from graph_rkd import find_best_n

# cost model (default): budget in edges/step
find_best_n(batch_size=128, edge_budget=1024)          # -> 17

# REAL measurement (when you have a GPU + the embedding methods):
#   feasible_fn(N) must be monotonic: True while it fits (no OOM / time ok)
find_best_n(128, edge_budget=0, feasible_fn=lambda N: roda_um_passo_ok(N))
```

If there are **diminishing returns** (quality is not pure "∝ N"), use
`find_knee_n(quality_fn, ...)`: binary search for the largest N whose relative
quality gain when doubling N still exceeds `rel_tol` (the "knee" of the curve).
`quality_fn(N)` is a real measurement (e.g.: recall/top-1 of the student).

## Derived mathematical rule

**partition** scheme (each sample used 1×): the batch is split into ⌊B/N⌋
disjoint complete graphs `K_N`. Edges per graph = `C(N,2) = N(N-1)/2`, so:

```
E (edges/step) = (B/N) · C(N,2) = B·(N-1)/2          (exact when N | B)
```

Note that **E grows only linearly in N** (doubling N ≈ doubles the cost, since the number of
graphs halves) — it is in this precise sense that "does not grow
exponentially" holds. Solving for the largest N under budget E:

```
B·(N-1)/2 ≤ E   ⟹   N* = ⌊ 2E/B + 1 ⌋     ⟹     (N*-1)·B = 2E = const
```

That is, **N\* is affine in 1/B** (`N* ≈ 2E/B + 1`). The empirical fit of
`derive_scaling_rule` over B ∈ {128…2048} reproduces this **exactly**
(`N* ≈ 2048·(1/B) + 1.00`, R² = 1.0000, residual ~10⁻¹⁴ for E=1024).

**sample** scheme (G fixed graphs of N nodes): `E = G·C(N,2)` ⟹
`N* ≈ sqrt(2E/G)`, **independent of B**.

> These rules come from the *cost model* (proxy = number of edges). When the
> embedding methods and the GPU are available, replace the predicate with a
> real measurement (`feasible_fn`/`quality_fn`) and re-derive — the functional form
> (affine in 1/B for partition; constant for sample) should hold if the cost
> of the embedding is ~linear in the number of edges.

## Graph embeddings (permutation-invariant)

Two deterministic embeddings of the whole graph from the distance
matrix (`embeddings.py`), both in **PyTorch and differentiable** (the student
side needs gradient):

1. **`node_profile_embedding(D, sort_key="lex")`** — Ordered Node Profile.
   Sorts the distances within each node (neighborhood profile), sorts the
   profiles among themselves and flattens. Fixed size `N·(N-1)`.
   - **Default `sort_key="lex"` (lexicographic), not `"mean"`.** Sorting by mean
     **breaks invariance on ties** (`argsort` breaks ties by the original
     position → changes under shuffling). The selftest demonstrates: with tied
     means, `mean` gives a difference of `2.0` under permutation; `lex` gives `0.0`. The
     `"mean"` option exists only for parity with the reference code.
2. **`mds_spectral_embedding(D)`** — classical MDS eigenvalues (spectrum of the
   Gram after double-centering of D²), in decreasing order. Fixed size `N`.
   Invariant under permutation similarity.

For distillation, pass `normalize=True` (default in the loss): it normalizes each
matrix by the mean distance, making the embedding **scale-invariant** — without
this the loss would compare the scale of the distances (teacher 512-d vs student
192-d), not the geometry.

Validation (`python -m graph_rkd.selftest`): exact parity with the reference
numpy; invariance (A vs shuffled = 0) and sensitivity (A vs B > 0) for
both methods; finite and non-zero gradient; and loss → 0 when
student == teacher.

## Adaptive graph sampling (`sampling`)

How many graphs to sample per step:

| `sampling` | graphs/step | when to use |
|---|---|---|
| `partition` | ⌊K/N⌋ (disjoint) | baseline; each sample used 1× |
| `random` | `graphs_per_step` (fixed) | manual control |
| **`log`** (recommended) | `G(N) = clamp(round(α·log₂ C(K,N)), g_min, g_max)` | **scales with the Pascal's triangle row** |

The **`log`** scheme makes the number of sampled graphs **grow with `C(K,N)`** (the
Pascal row value). Since `C(K,N)` is huge (~1e37), we scale with
`log₂ C(K,N)` — the *description length* (bits to specify one graph), which is
bounded, grows with the row and peaks at `N=K/2`. For K=128, α=0.5:

```
N:   2   4   8  16  32  64  96  127
G:   6  12  20  33  50  62  50    4
```

**Suggested values:** `α=0.5` (≈ half a graph per bit of the space; gives G∈[6,33] in the
practical regime N≤17), `g_min=⌊K/N⌋` (coverage ≥ partition, default), `g_max=64`
(cost ceiling; rarely active at small N). α=1.0 ≈ doubles the graphs (less
variance, more cost); α=0.25 ≈ half. Cost/step = `G·C(N,2)` edges.

> Honest statistical note: the number of samples for a fixed variance of a Monte
> Carlo estimator does **not** depend on the population size. Scaling with `log C(K,N)` is
> a reasonable heuristic ("more diversity ⇒ sample more"), not a theoretical
> requirement — the real gain is covering a more diverse space with more graphs when N
> grows, without ever enumerating it.

## Graph-RKD distillation loss

`GraphRKDLoss(method="profile"|"mds", n_nodes=N, sampling="partition"|"random"|"log", ...)`
generalizes RKD: it matches the N-node graph embedding between teacher and student
(same indices on both sides), instead of pairs (RKD-D) or triples (RKD-A).

```python
from graph_rkd import GraphRKDLoss, find_best_n

N = find_best_n(batch_size=128, edge_budget=1024)   # e.g.: 17
graph_rkd = GraphRKDLoss(method="profile", n_nodes=N, sampling="partition")

# in the training loop (student_emb, teacher_emb: (B, d)):
loss_graph = graph_rkd(student_emb, teacher_emb)     # teacher without grad internally
```

To plug into `distill_to_convnextmicro.py`: use the pooled embeddings of the
student/teacher (`forward_features(...)["embedding"]`) and add `graph_rkd_ratio *
loss_graph` to the total loss — instead of (or together with) `dist_ratio`/`angle_ratio`.

## Sampling-based contrastive loss (InfoNCE) — `contrastive.py`

A **lightweight, contrastive** alternative to the regression above (GraphSAGE/PinSage/
CRD style): the cost is **O(G·M)** (G graphs, M negatives), independent of the graph
space. Important: the regression `GraphRKDLoss` is **already O(G)** — the gain of
contrast is not avoiding a factorial (we never enumerate C(B,N)), but rather (a) limiting the
comparisons *between* graphs to M negatives and (b) the contrastive objective tends to
distill better than regression (CRD).

**cross-model** framing (distillation): anchor = graph i of the *student*;
positive = same graph i of the *teacher*; negatives = M graphs j≠i of the *teacher*
(sampled). Since the graph embedding depends only on N, anchor and positive
are in the same space (direct cosine).

```python
from graph_rkd import GraphContrastiveDistillLoss, find_best_n
N = find_best_n(128, edge_budget=1024)
crit = GraphContrastiveDistillLoss(method="profile", n_nodes=N,
                                   num_negatives=10, temperature=0.07)
loss_graph = crit(student_emb, teacher_emb)        # (B, d) each
```

Implementation notes (vs. the reference protocol):
- **Vectorized** (no per-sample `for`): negatives via `randint (A, M)` + gather.
- **Stable InfoNCE** with `cross_entropy(logits, 0)` — proven identical to the
  formula `-log(pos/(pos+Σneg))` over the same negatives (selftest).
- **`exclude_index`**: avoids drawing the positive itself as a negative (a bias that the
  raw `torch.randint` of the reference protocol has).
- `SampledGraphContrastiveLoss(temperature, num_negative_samples)` is the generic
  class with the requested `(anchor, positive, pool)` signature.

## Experiments: standard loss + Graph-RKD, binary search of N

`distill_to_convnextmicro.py` accepts the graph loss via flags
(`--graph_rkd_mode {regression,contrastive}`, `--graph_rkd_method {profile,mds}`,
`--graph_rkd_nodes N`, `--graph_rkd_ratio`, `--num_negatives`, `--temperature`),
added to the standard loss (CE + Hinton KD). Euclidean distance.

The `run_graph_rkd_search.py` orchestrator chooses N, for each (mode × method),
by a **budget-bounded log sweep** (replaces the old quality
binary search): (1) `N_max` ceiling by compute budget via exact binary
search (`find_best_n`); (2) log-spaced candidates in `[n_min, N_max]`
(`log_spaced_orders`, ~log₂N_max points); (3) each candidate trained with
`--seeds` seed(s), quality = best **validation** top-1 (mean); (4) selection
by `--select {argmax,1se}` (1se = one-standard-error rule, parsimony); (5) long
run at the chosen N. Binary search on *quality* was avoided: it requires a
monotone/noiseless curve, which is not guaranteed (see `select_order`/`log_spaced_orders`).

**Loss used in the experiments: only cross-entropy + the graph loss.** The
orchestrator turns off KD, RKD-D, RKD-A and attention (`kd/dist/angle/at = 0`), so
the only relational component is the graph one.

**Contrastive InfoNCE temperature:** **constant by default** (`--temp_start`,
τ=0.07) — it is the clean baseline, aligned with SimCLR/MoCo/CRD. The **schedule** is
an **optional ablation** (`--temp_schedule {linear,cosine,exp}` + `--temp_end`),
logged in `train/graph_temperature`. Careful when interpreting: lowering τ amplifies the
gradient by ~1/τ, so the schedule gets confounded with the LR scale; and
regression has no temperature (the reg×contr comparison is cleaner with fixed τ).

```bash
TEACHER_ARCH=resnet18 DATASET=cub200 bash examples/graph_rkd_search.sh
```

Output: table `(mode, method) -> N*, val@final`. Warning: it triggers many
distillations (use a GPU; adjust `--search_epochs`/`--final_epochs`).

## API

Choice of N / combinatorics:
- `unique_graphs(B, N)` / `ordered_tuples(B, N)` / `permutation_reduction(N)`
- `step_edge_cost(B, N, scheme, graphs_per_step)`
- `largest_feasible_n(predicate, lo, hi)` — generic monotonic binary search
- `find_best_n(batch_size, edge_budget, scheme, ..., feasible_fn=None)`
- `find_knee_n(quality_fn, lo, hi, rel_tol)`
- `derive_scaling_rule(batch_sizes, edge_budget, scheme, graphs_per_step)`
- `plot_unique_graphs(B, path)`

Graph embeddings / loss:
- `pairwise_distance_matrix(node_emb, squared)` / `normalize_distance_matrix(D)`
- `node_profile_embedding(D, sort_key, normalize)` (Method 1)
- `mds_spectral_embedding(D, normalize, jitter)` (Method 2)
- `node_profile_embedding_np(D)` (numpy reference) / `embed_graphs(...)`
- `sample_graphs(B, n_nodes, sampling, ...)` / `GraphRKDLoss(...)` (regression)
- `SampledGraphContrastiveLoss(...)` / `GraphContrastiveDistillLoss(...)` (InfoNCE)
